### Runtime boundaries and data flow

1. RHF Controller reads the selected browser File; Zod custom validation checks `typeof File !== "undefined"` before `instanceof File`, so importing/prerendering is safe without browser globals.
2. `useUpload` owns local active scope and a TanStack mutation. Upload is a mutation because it creates independently stored file chunks, rather than fetching cacheable server state. `retry: false` avoids accidental duplicate uploads; a ref lock guards repeated submit events before React rerenders.
3. React-free `uploadFile` creates FormData with field exactly `file`, then calls shared Axios. No manual multipart boundary/header, auth interceptor, credential mode, retry framework, or streaming wrapper was added. No arbitrary client timeout/file-size cap was invented for model-backed uploads.
4. Axios response data is `unknown`; Zod validates `id` UUID, `name` string, `type` string, `total` nonnegative integer, `chunks` array, each chunk's `text` string, integer `index`/`count`, and nullable/optional integer `page` and string `heading`/`section`. No new chunk-index/count restrictions were invented.
5. Only validated `id` becomes local `fileId`, with returned name/type/total. No client UUID is generated. No localStorage/sessionStorage/IndexedDB persistence; reload clears local scope.
6. Button/file input disable while pending, with visible processing text. A successful replacement changes active scope; a failed replacement keeps the last successful scope and shows an explicit error. Empty selection fails before transport. Unsupported/empty files remain backend validation responsibilities.
7. Known structured `{error, code}` failures show the backend's public error. Network/CORS/unstructured failures show a generic connection/retry error. Malformed success data cannot become active scope. Query provider creates one QueryClient per browser lifetime and fresh clients during prerender; no SSR data hydration machinery was added.
8. `environment.ts` validates the required public API URL; `environment-public.ts` is the only browser env read. HTTP(S), no credentials/query/fragment, whitespace trimming and trailing slash normalization. Next config uses the same validator so invalid/missing config fails before build. The API base is public and baked into the export; deployment changes require a rebuild.
9. Backend `CorsConstants` validates comma-separated `CORS_ORIGINS`. Default/blank resolves to an empty list. Exact HTTP(S) origins only, no wildcard, credentials, paths, query, fragment, whitespace, or invalid ports; duplicate origins are removed. `core/constants.py` loads dotenv and exposes the matching `cors` group. Main wires CORSMiddleware with POST, Content-Type and credentials false; Starlette handles OPTIONS. Safe examples permit localhost ports 3000 and 3001. Compose forwards the setting. CORS controls browser response access; it does not authenticate users or prevent non-browser requests.
